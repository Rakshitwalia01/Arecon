# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 2.0.x   | :white_check_mark: |
| < 2.0   | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability within ARECON 2.0, please follow responsible disclosure principles.

**Please do NOT report security vulnerabilities through public GitHub issues.**

Instead, please send an email directly to **Rakshit Walia** or use GitHub's private vulnerability reporting feature on this repository.

### What to Include in Your Report:
- A description of the vulnerability.
- Steps to reproduce or a minimal proof-of-concept (PoC).
- Affected module(s) or CLI/GUI components.
- Potential impact and suggested mitigations.

### Our Commitment:
- You will receive an acknowledgment within 48 hours.
- We will coordinate a fix and release a patched version before public disclosure.
- Security researchers who report vulnerabilities responsibly will be credited in our release notes.

## Authorized Use & Legal Disclaimer

ARECON 2.0 is designed exclusively for authorized penetration testing, security auditing, and bug bounty hunting within authorized scopes. Users must ensure they have explicit, documented authorization from target asset owners before executing active network scans.
